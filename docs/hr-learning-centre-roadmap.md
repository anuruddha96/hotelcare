# HotelCare HR Training & Development Centre — approved programme
Owner approval: 2026-11-27. Scope: all ten phases, sequential release gates; no unrelated changes.
## Release gates
- Phase 1: additive tenant-owned LMS foundation; preserve all legacy tour rows. Explicit course ownership; published versions immutable through administrative API. No cross-tenant user, course or file lookups. Initial schema is review SQL until scratch RLS tests and production preflight pass, then generate a migration via Supabase CLI. No automatic production data backfill.
- Phase 2: full-width HR training overview with status KPIs, guide/role/property comparisons, filters and drilldown; separate existing guide coverage from assigned training. Counts reflect eligible guide/account pairs; no made-up trends, time or deadlines.
- Phase 3: employee learning profile linked to People directory, read-only legacy evidence and new attempt history; former/unlinked staff distinguished. Historical records retained after account transfers, hidden from unauthorized current tenants.
- Phase 4: formal course assignments (individual or reviewed bulk cohort), due dates, mandatory flag, unique idempotency key and version pinning. Backend validates role, employee, course, organization, eligibility, date and duplicate assignment. Retraining creates new attempt; never delete existing evidence. Employee inbox and assignment-specific start/resume.
- Phase 5: configurable learning paths and onboarding 1/3/7/14/30-day milestones; HR preview/approval before mandatory enrollment; no automatic use of unverified job roles.
- Phase 6: organization-owned content drafts, versioned publish workflow, translations, private assets and safe file validation/scan. Shared guides copied into explicit tenant-owned course version snapshots; never trust a slug prefix as sole authorization for new course data.
- Phase 7: server-side assessment grading, question bank never exposed with correct answers, default 80% pass threshold, feedback/retakes with immutable results, practical supervisor sign-off, internal certificates only after criteria. Configurable expiry.
- Phase 8: assignment and deadline reminders 3/1 days, overdue and expiry, idempotent delivery log and retry, employee local working hours, weekly HR summary. No scheduler until dry-run and deduplication pass.
- Phase 9: Mira answers based on approved tenant content and current permissions; generated quiz/content drafts require HR approval. Never automatically mark completion. Localization across supported app languages; human review of operational translations.
- Phase 10: filtered Excel/CSV executive and employee matrix, onboarding, assessment, certification and deadline reporting. Authorized top-management read view and property/department-scoped supervisor view only after dedicated policy tests; no extra role grants in phase 1. Browser/mobile/light-dark and regression tests; merge exact tested SHA, apply migration and deploy verified edge dependencies before publishing frontend.
## Data and measurement semantics
Existing user_tour_progress and user_training_state are live operational guide state, not formal assignment/attempt history. Preserve them; label legacy completion evidence as such. An old completion does not prove a new course version or assessment was passed. Current legacy restart still deletes progress; retire HR restart only after new flow works, then secure legacy endpoints. Do not copy fabricated timestamps or map historical evidence to new assignments automatically.
For LMS, organization-owned course identity and immutable version snapshot are distinct; assignments reference exact versions, attempts reference assignments, event history append-only. Shared HotelCare content can be materialized as explicit tenant-owned snapshots, with source identity/version provenance. Formal status, overdue calculations, completion rate and assessment rate use clearly defined denominators; zero eligible is N/A. No employee performance rankings from guide completion alone.
## Initial implementation boundary
The first release is intentionally not the full LMS. Review schema uses RLS and authenticated SELECT-only grants; no learner/HR direct writes until transactional validated service/RPC implementation is reviewed. HR can manage only authorized non-protected employees; preserve current admin/top-management/controlling/HR exclusion. Tenant managers and top management do not gain access to new data until later policies pass. All legacy tables remain unchanged.
## Deployment
Use draft PR while gates remain open; current hourly general merge agent must not merge a draft or bypass checks. CI scratch fixtures are not a production replica; validate exact schema against production metadata before DDL. Create migration with Supabase CLI; apply only merged exact SQL, verify migration version, RLS/grants and tenant access; no service key in frontend. Retain all historical records; rollback via feature flag/read path, do not drop learning history. No production mutation without validated release gate.
