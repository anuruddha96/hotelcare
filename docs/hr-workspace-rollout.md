# HR workspace rollout — review checklist
Draft PR. Do not merge or publish before review.
- Existing workforce_staff remains the master. HR landing uses the staff scheduler; People and Attendance use their own screens.
- The proposed SQL is deliberately outside migrations: CLI unavailable in the authoring environment. Review docs/hr-personnel-storage.review.sql, generate a versioned migration using supabase migration new, test it on a disposable local database or preview branch, then approve production apply separately.
- Database room/ticket restrictions must be tested against direct authenticated reads/writes, security-definer RPCs, Edge Functions, and Mira; RLS does not constrain service-role callers. Preserve existing non-HR roles, including HR's existing revenue and finance entitlements pending explicit scope approval.
- Validate legacy workforce links; privileged identities cannot be newly attached/detached by HR after the proposed trigger. Test concurrent linking, deleted users, and tenant switches. No new invitation, account suspension, or automatic role changes are included.
- Private storage only, service endpoint checks current HR role and same-tenant staff identity on each call. Metadata and objects unavailable to direct client access. Signed downloads expire after 60 seconds; audit records describe issuance, not confirmed downloads. Uploads fail closed until an organization-approved HTTPS malware scanner returning {verdict:"clean"} is configured with HR_DOCUMENT_SCANNER_URL and HR_DOCUMENT_SCANNER_TOKEN; do not submit confidential documents to a public scanning provider.
- Document types in this first iteration: PDF, PNG, JPEG. No employee self-service sharing, inline preview, hard deletion, renewal versions, retention automation or bulk exports. Approve document categories and retention with HR/legal. Test upload MIME spoof, oversized file, scanner failure, object/metadata rollback, archived file access, unauthorized requests and private bucket configuration. Use synthetic files only.
- Training analytics are based on current role-applicable core curricula and V2 progress; legacy dismissal/pause state is shown. No-login staff are not counted as eligible accounts. Review tenant-specific curriculum conditions before treating coverage as a compliance KPI. Restart remains destructive and explicitly labeled. Actual due-date assignments, bulk assignment, versioned completion history and notifications require a separate V2 assignment model.
- CI must pass, and database/Edge Function integration and browser tests must be completed before production rollout. No production migration or deployment was performed.
